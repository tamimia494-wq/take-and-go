# Take & Go

منصة عربية لإدارة الكباتن والعمولات، بواجهتين منفصلتين للكابتن والإدارة، وواجهة API مشتركة. يستخدم المشروع PostgreSQL الموجود في Railway للتخزين، وGreen API لربط مجموعة واتساب، وRailway لاستضافة الخدمات.

## مكونات المشروع

- `apps/captain`: موقع الكابتن (منفصل في النشر).
- `apps/admin`: لوحة الإدارة (منفصلة في النشر).
- `apps/api`: المصادقة، الأرصدة، الجرد، الحسابات المالية، Webhook الخاص بـ Green API، والخصم الأسبوعي.
- Railway Postgres: قاعدة البيانات المشتركة بين المواقع والخدمات. استخدم قاعدة المشروع الموجودة ولا تنشئ قاعدة إنتاج إضافية.

## التشغيل المحلي

1. ثبّت Node.js 20 أو أحدث.
2. جهّز قاعدة PostgreSQL محلية للتطوير فقط، واضبط `DATABASE_URL` و`DIRECT_URL` في `.env`. لا توصل بيئة التطوير بقاعدة الإنتاج ولا تشغّل seed أو migrations عليها.
3. انسخ `.env.example` إلى `.env` واملأ بيانات قاعدة التطوير و`JWT_SECRET` وبيانات الإدارة. يمكن تأجيل متغيرات Green API إلى الخطوة الأخيرة؛ يعمل الـ API دونها، وتظل وظائف واتساب متوقفة حتى إعدادها.
4. من جذر المشروع شغّل:

   ```powershell
   npm install
   npm run db:generate
   npm run db:migrate
   npm run db:seed
   ```

5. شغّل الخدمات في نوافذ طرفية منفصلة:

   ```powershell
   npm run dev:api
   npm run dev:captain
   npm run dev:admin
   ```

6. افتح موقع الكابتن على `http://localhost:3001` ولوحة الإدارة على `http://localhost:3002`.

## ربط Green API

1. جهّز Instance مفعّلاً في Green API، وأضف رقم واتساب المتصل إلى المجموعة المستهدفة كمسؤول. قراءة قائمة المشاركين عبر `getGroupData` وحذف رسالة عضو يتطلبان الصلاحيات المناسبة في المجموعة.
2. أضف بيانات Instance وToken ومعرّف المجموعة إلى متغيرات `GREEN_API_INSTANCE_ID`, `GREEN_API_TOKEN`, و`GREEN_API_GROUP_ID`.
3. في إعدادات Webhook للـ Instance، اضبط عنوان Webhook إلى:

   `https://<api-domain>/webhooks/green-api`

   فعّل `incomingWebhook` وأدخل `Bearer <GREEN_API_WEBHOOK_TOKEN>` كرمز Webhook. يتحقق الـ API من ترويسة `Authorization`.
4. من لوحة الإدارة، استخدم زر المزامنة لاستيراد أعضاء المجموعة المحددة فقط. الحساب الجديد يبدأ بكلمة مرور مؤقتة `123456` ورصيد صفر؛ يجب على الكابتن تسجيل الدخول وإضافة اسمه قبل استخدام الحساب.
5. اكتب كلمة «سعر» ثم المبلغ مباشرة في سطر الطلب (مثال: `سعر 7 راكب` أو `سعر: 10 اوردر`). تُقبل الأرقام العربية والغربية. يُصنّف السطر الذي يحتوي «اوردر» أو «اوردرات» أو «الاوردرات» أو «اوردرين» (بما فيها صيغ الهمزة) كأوردر بسعر الإدارة للأوردر؛ وكل سطر آخر يُحسب كراكب بسعر الإدارة للراكب. تُقرّب قيمة كل سطر إلى أقرب مضاعف 5 (وعند التعادل يُقرّب للأعلى)، ثم تُحسب العمولة حسب تعرفة النوع لكل خمسة. مثال: أسعار 6 و7 تُقرّب إلى 5، و8 و9 إلى 10، و12 إلى 10، و13 إلى 15. عند اجتماع عدة أسطر، تُجمع عمولة كل سطر على رد الكابتن نفسه.
6. يرد الكابتن «تم» على رسالة الطلب. لا يُعتمد الرد 👍 إلا من صاحب رسالة الطلب الأصلية. تُخصم العمولة مرة واحدة عند الاعتماد، ويُعاد المبلغ نفسه عند وضع ❌ من صاحب الطلب أو صاحب الرد أو مسؤول المجموعة على رد «تم» المعتمد؛ تكرار الإلغاء لا يرد المبلغ مرتين. علامة الإلغاء قبل خصم العمولة لا تغيّر الرصيد. عند الموافقة على رد لا يُحذف؛ يُحذف الرد فقط إذا كان حساب الكابتن غير مفعّل أو رصيده غير كافٍ. يرسل النظام معرّف الرسالة الأصلي إلى Green API لحذفها من جميع المشاركين، ويعيد المحاولة عند فشل الطلب. حذف الرسالة للجميع متاح في واتساب خلال 60 ساعة من إرسالها؛ بعد ذلك يقتصر الحذف على المرسل.
   تحفظ خدمة API أحداث Green API قبل معالجتها، وتعيد محاولة الأحداث التي وصلت قبل تسجيل رسالة الطلب أو رد الكابتن تلقائياً حتى 60 ساعة؛ لا يُحتسب «تم» دون 👍 من صاحب الطلب.

> استورد أعضاء المجموعة فقط بعد التأكد من صلاحية استخدام أرقامهم وإبلاغ المشاركين بسياسة الخصوصية المناسبة. هذه المنصة لا تنفذ رسائل تسويقية أو تواصل جماعي.

## النشر على Railway

استخدم مشروع Railway الحالي وخدماته الثلاث وقاعدة Postgres المرتبطة به. لا تنشئ مشروعاً أو قاعدة بيانات إنتاج جديدة. اجعل **Root Directory** لكل خدمة `/`:

| الخدمة | Build Command | Start Command |
| --- | --- | --- |
| API | `npm ci && npm run build --workspace @take-and-go/api` | `npm run start --workspace @take-and-go/api` |
| Captain | `npm ci && npm run build --workspace @take-and-go/captain` | `npm run start --workspace @take-and-go/captain` |
| Admin | `npm ci && npm run build --workspace @take-and-go/admin` | `npm run start --workspace @take-and-go/admin` |

استخدم نطاق Railway مستقلاً لكل خدمة ويب (`captain`, `admin`) ونطاقاً لخدمة API. عيّن **Pre-deploy Command** لخدمة API إلى `npm run db:migrate --workspace @take-and-go/api` حتى تُطبق migrations قبل تشغيل الخدمة، وعيّن المتغيرات التالية:

- API: `DATABASE_URL`, `DIRECT_URL`, `JWT_SECRET`, `ADMIN_PASSWORD`, `GREEN_API_URL`, `GREEN_API_INSTANCE_ID`, `GREEN_API_TOKEN`, `GREEN_API_GROUP_ID`, `GREEN_API_WEBHOOK_TOKEN`, `CAPTAIN_APP_URL`, `ADMIN_APP_URL`, `TZ=Asia/Amman`.
- Captain وAdmin: `NEXT_PUBLIC_API_URL=https://<api-domain>/api`.
- `CAPTAIN_APP_URL` و`ADMIN_APP_URL` في خدمة API يجب أن يطابقا نطاقَي الويب دون `/` في النهاية.
- قاعدة Railway Postgres مشتركة؛ لا تضع بيانات الاتصال في إعدادات الواجهتين الأماميتين.

بعد إعداد قاعدة Railway الحالية لأول مرة فقط، شغّل seed مرة واحدة في Railway Shell:

```powershell
npm run db:seed --workspace @take-and-go/api
```

يسجل المسؤول الدخول بكلمة المرور فقط. ينشئ seed حساب الإدارة من `ADMIN_PASSWORD`، ولا يقبل كلمة المرور الافتراضية الموجودة في ملف المثال. لا تعِد تشغيل seed مع كل نشر لأنه يعيد تعيين كلمة مرور الإدارة. استخدم كلمة مرور قوية وفريدة واحفظها في متغير Railway السري؛ لا تضعها في Git أو المحادثات.

## المحاسبة

- كل القيم المالية محفوظة بوحدة الفلس الصحيحة لتجنب أخطاء الكسور العشرية.
- تُحفظ العمولة وقت تسجيل رسالة الطلب؛ تغيير التسعيرة يؤثر في الطلبات الجديدة فقط.
- عمليات الخصم والشحن تُسجل في دفتر الحركات ضمن معاملات قاعدة البيانات.
- يخصم النظام أرضية المجموعة يوم الخميس 23:59 بتوقيت `Asia/Amman` من حسابات الكباتن المفعّلة. لكل أسبوع مفتاح فريد لمنع الخصم المكرر عند إعادة تشغيل الخدمة.
- شحن الرصيد يدوي من لوحة الإدارة، ويظهر في سجل الكابتن والأدمن.
