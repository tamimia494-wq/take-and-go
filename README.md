# Take & Go

منصة عربية لإدارة الحجوزات والكباتن والعمولات، بواجهات منفصلة للعملاء والكباتن والإدارة، وواجهة API مشتركة. يستخدم المشروع PostgreSQL الموجود في Railway للتخزين، وربطاً مباشراً بواتساب عبر مكتبة Baileys (مجاني ودون وسيط) لإدارة مجموعة واتساب، وRailway لاستضافة الخدمات.

## مكونات المشروع

- `apps/customer`: صفحة حجز العميل واختيار المواقع والخدمات وإرسال الطلب المحفوظ إلى واتساب.
- `apps/captain`: موقع الكابتن (منفصل في النشر).
- `apps/admin`: لوحة الإدارة (منفصلة في النشر).
- `apps/api`: المصادقة، الحجوزات، الأرصدة، الجرد، الحسابات المالية، ربط واتساب المباشر، والخصم الأسبوعي.
- Railway Postgres: قاعدة البيانات المشتركة بين المواقع والخدمات. استخدم قاعدة المشروع الموجودة ولا تنشئ قاعدة إنتاج إضافية.

## إنشاء حسابات الكباتن

- يستطيع الكابتن إرسال طلب إنشاء حساب بالاسم ورقم الهاتف؛ لا يُنشأ الحساب ولا يمكن تسجيل الدخول قبل موافقة الإدارة.
- تراجع الإدارة الطلبات المعلقة وتوافق عليها أو ترفضها، ويمكنها أيضاً إنشاء حساب مباشرة بالاسم ورقم الهاتف.
- الحسابات المنشأة بهذه الطريقة تبدأ بكلمة مرور مؤقتة `123456`، ويُنصح بتغييرها فور تسجيل الدخول.

## التشغيل المحلي

1. ثبّت Node.js 20 أو أحدث.
2. جهّز قاعدة PostgreSQL محلية للتطوير فقط، واضبط `DATABASE_URL` و`DIRECT_URL` في `.env`. لا توصل بيئة التطوير بقاعدة الإنتاج ولا تشغّل seed أو migrations عليها.
3. انسخ `.env.example` إلى `.env` واملأ بيانات قاعدة التطوير و`JWT_SECRET` وبيانات الإدارة. يمكن تأجيل `WHATSAPP_GROUP_ID` وربط رقم البوت إلى الخطوة الأخيرة؛ يعمل الـ API دونهما، وتظل وظائف واتساب متوقفة حتى إعدادهما.
4. من جذر المشروع شغّل:

   ```powershell
   npm install
   npm run db:generate
   npm run db:migrate
   npm run db:seed
   ```

5. شغّل الخدمات في نوافذ طرفية منفصلة:

   ```powershell
   npm run dev:api
   npm run dev:customer
   npm run dev:captain
   npm run dev:admin
   ```

6. افتح صفحة العملاء على `http://localhost:3000`، وموقع الكابتن على `http://localhost:3001`، ولوحة الإدارة على `http://localhost:3002`. إدارة إعدادات الحجز متاحة من رابط «إدارة الحجوزات» داخل لوحة الإدارة.

تتطلب صفحة العملاء ترحيلاً جديداً لقاعدة البيانات. ينشئ العميل حسابه برقم هاتف أردني وكلمة مرور يختارها (6 أحرف على الأقل)، ويُفعّل الحساب تلقائياً ويدخل إلى الحجز مباشرة. تُخزّن كلمة المرور كـ hash، ويُوقف تسجيل الدخول مؤقتاً بعد خمس محاولات خاطئة. لا يوجد تحقق برسالة SMS في النسخة الحالية؛ لذلك لا تثبت ملكية رقم الهاتف قبل إضافة مزود تحقق مناسب.

## ربط واتساب (Baileys)

يتصل النظام بواتساب مباشرة برقم البوت عبر مكتبة Baileys، دون Green API أو أي خدمة وسيطة.

1. أضف رقم البوت إلى المجموعة المستهدفة واجعله **مسؤولاً (أدمن)**؛ حذف رسائل الأعضاء وإزالتهم يتطلبان ذلك.
2. ضع معرّف المجموعة في `WHATSAPP_GROUP_ID` (مثال: `120363XXXXXXXXXXXX@g.us`). ما زال `GREEN_API_GROUP_ID` القديم مقبولاً إن كان مضبوطاً.
3. من لوحة الإدارة، قسم «ربط واتساب»، اضغط «ربط رقم البوت (عرض QR)»، ومن جوال رقم البوت: واتساب ← الأجهزة المرتبطة ← ربط جهاز، وامسح الرمز. تُحفظ الجلسة في قاعدة البيانات فتبقى بعد إعادة النشر.
   تصل رسائل الجروب عبر هذا الربط وتُحفظ في قاعدة البيانات لمدة 3 أيام قبل معالجتها، فيستطيع النظام استرجاع الطلبات والردود و👍 الفائتة وحذف الرسائل بعد إعادة التشغيل. الرسائل التي تصل أثناء توقف الخدمة يسلّمها واتساب عند إعادة الاتصال. عند فصل الربط لا يقرأ النظام الجروب ولا يحذف رسائل حتى يُربط من جديد.
4. من لوحة الإدارة، استخدم زر المزامنة لاستيراد أعضاء المجموعة المحددة فقط. الحساب الجديد يبدأ بكلمة مرور مؤقتة `123456` ورصيد صفر؛ يجب على الكابتن تسجيل الدخول وإضافة اسمه قبل استخدام الحساب.
5. اكتب إحدى كلمات «سعر» أو «أجرة» أو «توصيل» أو «حسابه» ثم المبلغ مباشرة في سطر الطلب (مثال: `سعر 7 راكب` أو `أجرة: 10 اوردر` أو `توصيل 12`). تُقبل الأرقام العربية والغربية. يُصنّف السطر الذي يحتوي «اوردر» أو «اوردرات» أو «الاوردرات» أو «اوردرين» (بما فيها صيغ الهمزة) كأوردر بسعر الإدارة للأوردر؛ وكل سطر آخر يُحسب كراكب بسعر الإدارة للراكب. تُقرّب قيمة كل سطر إلى أقرب مضاعف 5 (وعند التعادل يُقرّب للأعلى)، ثم تُحسب العمولة حسب تعرفة النوع لكل خمسة. مثال: أسعار 6 و7 تُقرّب إلى 5، و8 و9 إلى 10، و12 إلى 10، و13 إلى 15. عند اجتماع عدة أسطر، تُجمع عمولة كل سطر على رد الكابتن نفسه.
6. يرد الكابتن «تم» على رسالة الطلب. لا يُعتمد الرد 👍 إلا من صاحب رسالة الطلب الأصلية. تُخصم العمولة مرة واحدة عند الاعتماد، ويُعاد المبلغ نفسه عند وضع ❌ من صاحب الطلب أو صاحب الرد أو مسؤول المجموعة على رد «تم» المعتمد؛ تكرار الإلغاء لا يرد المبلغ مرتين. علامة الإلغاء قبل خصم العمولة لا تغيّر الرصيد. عند الموافقة على رد لا يُحذف؛ يُحذف الرد فقط إذا كان حساب الكابتن غير مفعّل أو رصيده غير كافٍ. يحذف النظام الرسالة لجميع المشاركين عبر الربط المباشر، ويعيد المحاولة عند الفشل. حذف الرسالة للجميع متاح في واتساب خلال 60 ساعة من إرسالها؛ بعد ذلك يقتصر الحذف على المرسل.
   تحفظ خدمة API رسائل الجروب قبل معالجتها، وتعيد محاولة الأحداث التي وصلت قبل تسجيل رسالة الطلب أو رد الكابتن تلقائياً حتى 60 ساعة؛ لا يُحتسب «تم» دون 👍 من صاحب الطلب.

> استورد أعضاء المجموعة فقط بعد التأكد من صلاحية استخدام أرقامهم وإبلاغ المشاركين بسياسة الخصوصية المناسبة. هذه المنصة لا تنفذ رسائل تسويقية أو تواصل جماعي.

## النشر على Railway

استخدم مشروع Railway الحالي وقاعدة Postgres المرتبطة به، وأضف خدمة الواجهة الجديدة للمشروع نفسه. لا تنشئ مشروعاً أو قاعدة بيانات إنتاج جديدة. اجعل **Root Directory** لكل خدمة `/`:

| الخدمة | Build Command | Start Command |
| --- | --- | --- |
| API | `npm ci && npm run build --workspace @take-and-go/api` | `npm run start --workspace @take-and-go/api` |
| Customer | `npm ci && npm run build --workspace @take-and-go/customer` | `npm run start --workspace @take-and-go/customer` |
| Captain | `npm ci && npm run build --workspace @take-and-go/captain` | `npm run start --workspace @take-and-go/captain` |
| Admin | `npm ci && npm run build --workspace @take-and-go/admin` | `npm run start --workspace @take-and-go/admin` |

استخدم نطاق Railway مستقلاً لكل خدمة ويب (`customer`, `captain`, `admin`) ونطاقاً لخدمة API. عيّن **Pre-deploy Command** لخدمة API إلى `npm run db:migrate --workspace @take-and-go/api` حتى تُطبق migrations قبل تشغيل الخدمة، وعيّن المتغيرات التالية:

- API: `DATABASE_URL`, `DIRECT_URL`, `JWT_SECRET`, `ADMIN_PASSWORD`, `WHATSAPP_GROUP_ID`, `WHATSAPP_EXCLUDED_PHONES` (اختياري: أرقام إدارة لا تُحذف رسائلها ولا تُزال)، `CUSTOMER_APP_URL`, `CAPTAIN_APP_URL`, `ADMIN_APP_URL`, `TZ=Asia/Amman`.
- Customer وCaptain وAdmin: `NEXT_PUBLIC_API_URL=https://<api-domain>/api`.
- `CUSTOMER_APP_URL`, `CAPTAIN_APP_URL`, و`ADMIN_APP_URL` في خدمة API يجب أن تطابق نطاقات الويب دون `/` في النهاية. يمكن وضع أكثر من نطاق مفصولة بفاصلة (مثال: نطاق Railway ونطاق مخصص).
- في التطوير المحلي، إذا لم يُضبط `NEXT_PUBLIC_API_URL` لصفحة العملاء فإنها تتصل بالمنفذ 4000 على نفس العنوان الذي فُتحت منه الصفحة، فتعمل من الجوال على نفس شبكة الواي فاي.
- قاعدة Railway Postgres مشتركة؛ لا تضع بيانات الاتصال في إعدادات الواجهتين الأماميتين.

بعد إعداد قاعدة Railway الحالية لأول مرة فقط، شغّل seed مرة واحدة في Railway Shell:

```powershell
npm run db:seed --workspace @take-and-go/api
```

يسجل المسؤول الدخول بكلمة المرور فقط. ينشئ seed حساب الإدارة من `ADMIN_PASSWORD`، ولا يقبل كلمة المرور الافتراضية الموجودة في ملف المثال. إعادة تشغيل seed لا تغيّر كلمة مرور موجودة؛ غيّرها من زر «تغيير كلمة المرور» في لوحة الإدارة. إذا فُقدت كلمة المرور، ضع `ADMIN_PASSWORD` الجديدة و`ADMIN_PASSWORD_RESET=true` في خدمة API لنشر واحد، ثم احذف `ADMIN_PASSWORD_RESET`. استخدم كلمة مرور قوية وفريدة واحفظها في متغير Railway السري؛ لا تضعها في Git أو المحادثات.

## المحاسبة

- كل القيم المالية محفوظة بوحدة الفلس الصحيحة لتجنب أخطاء الكسور العشرية.
- تُحفظ العمولة وقت تسجيل رسالة الطلب؛ تغيير التسعيرة يؤثر في الطلبات الجديدة فقط.
- عمليات الخصم والشحن تُسجل في دفتر الحركات ضمن معاملات قاعدة البيانات.
- تدقيق العمولات من لوحة الإدارة يقارن حركات خصم وإضافة العمولة بحالة الطلبات والردود، ويعرض الفروقات والإصلاحات الممكنة. هذا الفحص لا يُعد تدقيقاً شاملاً لكل أنواع حركات الرصيد.
- يخصم النظام أرضية المجموعة يوم الخميس 23:59 بتوقيت `Asia/Amman` من حسابات الكباتن المفعّلة. لكل أسبوع مفتاح فريد لمنع الخصم المكرر عند إعادة تشغيل الخدمة.
- يبقى 0.5 د.أ محجوزة في رصيد كل كابتن ولا يمكن صرفها أو سحبها، حتى تُخصم منها أرضية الجروب. يأخذ الكابتن الطلب فقط إذا بقي معه 0.5 د.أ على الأقل بعد خصم العمولة (مثال: رصيد 1 د.أ وعمولة راكب 0.75 تترك 0.25، فيُرفض الرد ويُحذف). يستطيع الكابتن تنزيل الطلبات (الإنتاج) ورصيده 0.5 د.أ.
- الإزالة من الجروب: عند تشغيلها من لوحة الإدارة، يُزال كل 5 دقائق (10 أعضاء كحد أقصى في كل مرة) كل عضو حسابه غير مفعّل أو موقوف أو رصيده صفر، ويصله تنبيه خاص بالسبب. لا تُزال أرقام الإدارة والبوت ومشرفو الجروب والأرقام التي لا تملك حساباً. تحتاج الإزالة أن يكون رقم البوت أدمن في الجروب، وإرجاع العضو يدوي.
- شحن الرصيد يدوي من لوحة الإدارة، ويظهر في سجل الكابتن والأدمن.
